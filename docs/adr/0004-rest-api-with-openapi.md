# 0004 REST API with OpenAPI

Status: Accepted · Date: 2026-10-27

## Context
Part of the YapSpace MVP architecture (see docs/architecture/overview.md). Decision area: rest api with openapi.

## Decision
REST under /v1 with problem+json errors, keyset pagination, and an OpenAPI 3.1 document generated by utoipa. The extension types come from that document.

## Alternatives considered
- GraphQL: caching, complexity limits and abuse surface, with no client that needs flexible queries.
- gRPC: browsers need a proxy.

## Reasons
- The document is the contract, and CI fails when it drifts from the code.
- Keyset pagination stays fast on large tables.

## Consequences
- Generated documents need the routes! macro for every handler.
- Clients must ignore unknown fields.

## Revisit when
- Clients need flexible aggregation that REST cannot serve well.
