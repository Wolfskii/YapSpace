# Browser extension architecture

> Source of truth for this topic. Section letters (§X) refer to the original plan; the map is in [docs/plan/README.md](../plan/README.md#section-map). Change decisions only via an ADR / `docs/plan/decisions.md`.

## I. Browser extension architecture

### I.1 Decisions
- **WXT 0.21 + `@wxt-dev/module-svelte` + Svelte 5 (runes) + TypeScript (strict)**, built with npm. One codebase →
  `wxt build` (Chrome MV3) and `wxt build -b firefox --mv3` (Firefox MV3). WXT generates each manifest, handles the background differences
  (a service worker on Chromium, an event page on Firefox), and provides `browser` (the webextension-polyfill-style API), `defineContentScript`,
  runtime-registered content scripts, and `fakeBrowser` for tests.
- **UI surface = a floating panel in an extension iframe** inside a closed shadow root, injected on demand.
  *Why not render Svelte directly in a shadow root?* The iframe gives a separate origin: page CSS and JS can't touch it, the page CSP
  doesn't apply to the panel's fetch/WebSocket calls, and the WebSocket lives in a normal extension page (no MV3 service-worker keepalive
  problems). *Why not the browser side panel?* `chrome.sidePanel` and Firefox's `sidebar_action` use different APIs and UX. A
  side panel is a good Phase 6 option that reuses the same `panel.html`.
  *Fallback if the iframe is blocked on some site (Risk R-03):* render the same Svelte root inside the shadow root with
  `createShadowRootUi`, and proxy fetch/WS through the background. This is only implemented if the spike (P4-02) finds blocking sites.
- **Lightweight when inactive:** nothing is injected until the user clicks. The background only listens for `action.onClicked`,
  `commands.onCommand` and messages.

### I.3 Runtime flow
1. `browser.action.onClicked(tab)` or `commands.onCommand('toggle-panel')` → `browser.scripting.executeScript({target:{tabId},
   files:['/content-scripts/panel-host.js']})`. If that fails (chrome://, the web store, PDF viewer, about:, file://) → `action.setBadgeText({tabId,
   text:'×'})` + `setTitle('YapSpace can't run on this page')`, cleared after 4 s.
2. `panel-host` content script: if `globalThis.__yapspace` exists → toggle the visibility of the existing host and return. Otherwise create
   `<yapspace-root>` (`position:fixed; right:16px; bottom:16px; width:380px; height:min(640px, calc(100vh - 32px)); z-index:2147483647;`
   all styles inline, `all: initial`), attach a closed shadow root, append `<iframe src=browser.runtime.getURL('/panel.html')
   style="border:0;width:100%;height:100%;border-radius:12px;box-shadow:…" allow="clipboard-write">`. Then send
   `{type:'page-context', url: prefilter(location.href), canonical, title}` to the background. Listen to `ctx.addEventListener(window,
   'wxt:locationchange', …)` → resend the context (with the canonical rule from E.5 step 7). Listen for `{type:'panel-close'|'panel-minimize'}` from the background.
3. Background: `contexts: Map<tabId, PageContext>`, `ports: Map<tabId, Port>`. On `page-context` (sender.tab.id) → store it and post it to the port
   if one is connected. On `runtime.onConnect` (name `panel`, sender.tab.id) → store the port and post the current context.
   Clean up both maps on `browser.tabs.onRemoved` (this event needs no `tabs` permission) and remove the port on `port.onDisconnect`.
   Note: MV3 service workers can be terminated; the content script resends the context when the port reconnects (the panel reconnects the port on disconnect).
4. Panel (Svelte): connects the port and receives the context → `discussion.load(context)`: `POST /resolve` → state:
   `unsupported` (422 url_unsupported) | `no_discussion` (empty state: "Be the first to start the conversation") |
   `ready` (fetch the newest 50, open/reuse the RealtimeClient, subscribe) | `error`. A new context (SPA nav) → unsubscribe the old discussion and load the new one.
5. Posting: `client_msg_id = crypto.randomUUID()`. Insert a pending item. If there is no discussion yet, call `POST /discussions` first, then subscribe. Then post.
   Retry on network error with the same `client_msg_id` (up to 3 times). On success, replace the pending item with the server message (dedupe by `id`/`seq`).
   On 429, show a cooldown using `retry_after_s`.

### I.4 UX & accessibility
- The header shows the page title (truncated), the site, and buttons: minimize (collapses to a 48 px round button), settings, close. Keyboard: `Alt+Y` toggles
  (`commands`, user-changeable). Enter sends and Shift+Enter adds a newline. Esc closes dialogs.
- The message list scrolls to the bottom on open. "Load older" runs via an `IntersectionObserver` on a top sentinel and keeps the scroll position.
  A "New messages ↓" pill appears when the user has scrolled up. At most 1000 messages are kept in the DOM (older ones are dropped from memory, and the button re-fetches them).
- States: loading skeleton, empty, unsupported page (with the reason in plain words), signed-out composer ("Sign in to join"), offline banner
  ("Reconnecting…" with a live countdown), suspended notice, locked discussion notice, error with retry.
- a11y: the list is `role="log"` `aria-live="polite"` (announcements throttled to at most 1 per 2 s), every control has a label, visible focus rings,
  4.5:1 contrast, `prefers-reduced-motion` and `prefers-color-scheme` are respected. Run axe-core checks in component tests.
- i18n: every user-visible string comes from `_locales/en/messages.json` via `t()`.

### I.5 Website-specific behavior
The MVP has **page-level** identity plus server-side URL adapters (§E.4). In feeds (timelines), the discussion is about the feed page itself. The panel
header shows *what* is being discussed (title + display_url) so users can spot a wrong association and report it with
`wrong_discussion`. Phase 6 (P6-11) adds optional **content adapters** (`src/adapters/<site>.ts`) that find post permalinks inside
feeds (e.g. a "Discuss" button next to each tweet). Each adapter is isolated, feature-flagged, and fails closed (if a selector isn't
found, the generic page behavior applies).

### I.6 Distribution
Chrome Web Store (zip from `wxt zip`), Firefox AMO (`wxt zip -b firefox` + a sources zip, because AMO requires the source for bundled code). Edge Add-ons
accepts the Chrome zip. Safari needs Xcode packaging (later). `docs/extension/store-submission.md` covers listing text,
permission justifications ("activeTab: read the URL of the page you choose to discuss"), the privacy disclosures, and screenshots.
